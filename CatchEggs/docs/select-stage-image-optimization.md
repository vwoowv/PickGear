# 모드 선택 이미지 최적화 검증

검증일: 2026-09-18. 대상: CatchEggs, Cocos Creator 3.8.6.

## 변경

- `assets/resources/textures/SelectStage/Level{One,Two,Three}_A.png`를 각각 1146×2037에서 720×1280으로 축소했다. 원본 비율과 알파 채널을 유지하고 Lanczos3 리샘플링을 사용했다.
- 편집용 소스는 무손실 PNG로 저장했다. 세 파일 합계는 3,394,544 → 1,436,496바이트다.
- 세 이미지에만 `SelectStageWeb` 압축 프리셋을 적용했다. 웹 빌드에서 WebP 품질 90과 PNG 품질 95 대체 파일을 생성한다. 기존 `ExportWeb` 프리셋은 유지했다.
- 이미지·Texture·SpriteFrame UUID와 리소스 경로를 보존했다. Creator 재임포트가 축소된 이미지의 크기·트림·UV 정보를 갱신했다.
- `main.scene`에서 해당 이미지를 사용하는 Sprite 6개(모드 선택 3개, 로딩 화면 3개)의 SizeMode만 TRIMMED에서 CUSTOM으로 변경했다. 기존 UITransform 크기, 노드 위치·스케일, 터치 콜라이더와 컴포넌트 참조를 보존해 이미지 축소가 버튼 크기를 바꾸지 않도록 했다.

## 실제 웹 빌드 이미지 용량

기존 커밋 `c2a0927`의 이미지와 압축 설정을 별도 임시 프로젝트에서 빌드한 결과를 비교했다. 현재 프로젝트와 동일한 Creator 버전 및 web-mobile 빌드 옵션을 사용했다. 아래 수치는 해당 이미지 파일의 바이트 수이며 HTTP 헤더와 다른 게임 리소스는 포함하지 않는다.

| 이미지 | 기존 PNG | 변경 후 WebP | 변경 후 PNG 대체 |
| --- | ---: | ---: | ---: |
| LevelOne_A | 221,479 | 35,400 | 229,246 |
| LevelTwo_A | 396,574 | 67,814 | 195,405 |
| LevelThree_A | 250,150 | 41,866 | 122,910 |
| 합계 | 868,203 | 145,080 | 547,561 |

- WebP 사용 시 합계 약 848 → 142 KiB, **83.3% 감소**.
- PNG 대체 사용 시 합계 **36.9% 감소**. 개별 LevelOne PNG는 기존보다 크지만, 품질을 우선한 대체 포맷 설정을 유지했다.
- 전체 픽셀 수는 **60.5% 감소**했다. 실제 GPU 메모리 사용량은 별도 측정하지 않았다.
- 임시 기준 프로젝트는 스크립트 클래스 등록 경고가 있어 게임 동작 검증에는 사용하지 않았다. 크기와 압축 설정을 확인한 위 세 이미지의 인코딩 결과만 비교에 사용했다.

## 검증

- 현재 프로젝트 에셋 재임포트 및 web-mobile 빌드 성공. 현재 프로젝트 빌드에서 Missing class/Compile Error 없음. 기존 displayFBX 이름 및 순환 의존성 경고는 남아 있다.
- Creator Preview에서 모드 선택 이미지의 텍스트·알파 경계·배치를 확인하고 두 번째 모드의 선택, 게임 진행과 결과 화면을 확인했다.
- 로컬 웹 빌드에서 첫 번째 및 세 번째 모드의 선택, 로딩 화면, 게임 진행과 결과 화면을 확인했다.
- 웹 서버 요청 로그에서 세 이미지 모두 `.webp` 요청을 확인했다. 현재 브라우저의 WebP 경로를 검증했으며 WebP 미지원 브라우저에서 PNG 대체 선택은 실기기 검증하지 않았다.
- Preview와 웹 빌드 브라우저 콘솔에서 오류 없음. 세 번째 모드에서 기존 `spawnRandomEgg`의 x 위치 재시도 초과 경고가 2회 발생했으며 게임 진행은 계속됐다.
- JSON 비교로 씬 변경이 Sprite 6개의 `_sizeMode`뿐임을 확인했다. 이미지와 하위 에셋 UUID 보존, `git diff --check` 통과.

이는 모드 선택 이미지 전송량을 줄이는 변경이다. 실제 배포 서버·모바일 기기의 캐시 없는 접속부터 모드 선택까지 걸리는 시간은 아직 측정하지 않았다.
