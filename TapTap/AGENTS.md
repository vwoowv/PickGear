# TapTap 작업 지침

## 프로젝트 기준

- 이 폴더는 Cocos Creator `3.8.8`로 생성한 `TapTap` 프로젝트다. 버전 근거는 `package.json`의 `creator.version`이다.
- Creator 3.x API만 사용한다. `cc.Class`, `cc.loader` 같은 Creator 2.x 전역 API를 섞지 않는다.
- 현재 프로젝트는 2D 구성이며 `settings/v2/packages/engine.json`에서 2D 모듈이 활성화되고 3D 모듈은 비활성화되어 있다.
- 목표 플랫폼은 모바일 웹이다. 현재 로컬 빌드 프로필은 `web-mobile`, 출력 이름은 `web-mobile`이다.
- 프로젝트는 초기 상태다. 아직 시작 씬, 게임 스크립트, 테스트, 패키지 매니저, CI가 없다.

## 실제 작업 및 검증 절차

- 이 프로젝트에는 npm 스크립트나 검증용 셸 명령이 없다. 존재하지 않는 `npm test`, `npm run build` 같은 명령을 가정하지 않는다.
- Cocos Creator 3.8.8로 프로젝트를 열고 에셋 임포트가 끝날 때까지 기다린다.
- 변경 후 Console에서 새 스크립트 오류, 직렬화 오류, 누락 에셋 경고가 없는지 확인한다.
- 영향을 받은 씬과 프리팹을 Editor에서 열어 컴포넌트 및 직렬화 프로퍼티 연결을 확인한다.
- 가장 작은 변경 경로를 브라우저 Preview로 직접 실행한다.
- 플랫폼 관련 변경은 Build 패널에서 `Web Mobile`을 선택해 빌드하고 결과물을 브라우저에서 확인한다.
- 시작 씬이 생기기 전에는 프로젝트의 빌드 가능성을 주장하지 않는다.

## 디렉터리와 파일 역할

- `assets/`: 게임 코드와 Editor 관리 에셋이 들어가는 소스 루트다. 새 게임 콘텐츠는 이 아래에 둔다.
- `settings/`: 공유할 Cocos 프로젝트 설정이다. 변경 시 설정 diff와 의도를 함께 검토한다.
- `profiles/`: 현재 `.gitignore`에 포함된 로컬 Editor 상태다. 팀 공용 동작의 유일한 근거로 삼지 않는다.
- `package.json`: 프로젝트 이름, UUID, Creator 버전을 기록한다. 일반 npm 패키지 설정 파일로 가정하지 않는다.
- `tsconfig.json`: Cocos가 생성하는 `temp/tsconfig.cocos.json`을 확장하며 현재 `strict`는 `false`다.
- `library/`, `temp/`, `local/`, `build/`: 생성 캐시 또는 빌드 결과다. 소스처럼 직접 수정하거나 리뷰 대상으로 삼지 않는다.

## TypeScript 및 컴포넌트 규칙

- 새 엔진 코드는 Creator 3.x 방식으로 `cc`에서 모듈을 import한다.
- 씬에 부착할 컴포넌트는 `_decorator`, `@ccclass`, 필요한 `@property`와 `Component`를 사용한다.
- 엔진 객체에 의존하는 초기화는 일반 생성자보다 `onLoad`, `onEnable`, `start` 등 적절한 생명주기 메서드에 둔다.
- 이벤트 구독은 대응하는 생명주기에서 반드시 해제한다. 예를 들어 `onEnable`에서 등록하면 `onDisable`에서 해제한다.
- 프레임마다 실행되는 `update`에서는 불필요한 객체 생성, 반복 검색, 에셋 로드를 피한다.
- 현재 코드 스타일의 선례가 없으므로 대규모 아키텍처나 공통 프레임워크를 먼저 도입하지 않는다. 첫 구현에서 작고 명확한 구조를 세운 뒤 일관되게 확장한다.
- 기존 파일이 생긴 뒤에는 인접 코드의 import 순서, 이름, 생명주기 구성, 접근 제한자 스타일을 우선 따른다.

## Cocos 에셋과 직렬화

- 에셋 파일 또는 디렉터리는 대응하는 `.meta`와 함께 추가, 이동, 이름 변경, 복사, 삭제한다.
- `.meta`의 UUID는 씬과 프리팹 참조의 일부다. 충돌 해결을 위해 임의로 삭제하거나 재생성하지 않는다.
- 씬, 프리팹, 머티리얼, 애니메이션, 아틀라스, 임포트 설정은 Editor 소유의 직렬화 데이터로 취급한다.
- 위 직렬화 파일의 생성과 구조 변경은 가능한 한 Cocos Creator의 Assets/Scene 패널에서 수행한다.
- 직접 텍스트 편집이 꼭 필요하면 변경 범위를 작게 유지하고 UUID 관계, Editor 재임포트, 관련 씬 또는 프리팹 실행을 검증한다.
- `@ccclass` 식별자, 컴포넌트 클래스명, 직렬화된 `@property` 이름을 바꾸면 기존 씬 및 프리팹 연결이 깨질 수 있다. 변경 전 마이그레이션 계획과 Editor 검증이 필요하다.

## 변경 경계

항상 수행한다:

- 프로젝트 버전을 3.8.8 기준으로 유지하고 가장 좁은 범위의 Editor 검증을 수행한다.
- 소스 에셋과 `.meta` 쌍을 보존하고 누락된 참조가 없는지 확인한다.
- 모바일 웹에서 화면 크기, 터치 입력, 포커스 복귀 동작을 변경 범위에 맞게 점검한다.

먼저 확인한다:

- Creator 버전 업그레이드, 렌더 파이프라인 또는 물리 백엔드 변경, 패키지나 확장 기능 추가
- 빌드 플랫폼 또는 공유 프로젝트 설정 변경, 번들 경계 변경
- 직렬화된 타입이나 프로퍼티 이름 변경, Editor 밖에서 씬 또는 프리팹 구조 수정
- 네이티브 플랫폼이나 플랫폼별 SDK 도입

절대 하지 않는다:

- `library/`, `temp/`, `local/`, `build/`의 파일을 권위 있는 소스로 수정하거나 커밋하지 않는다.
- Creator 2.x와 3.x API를 혼용하지 않는다.
- 임포트 또는 병합 문제를 해결하려고 `.meta`를 무작정 삭제하지 않는다.
- 비밀키, 토큰, 서명 파일, 개인 머신의 절대 경로를 저장소에 기록하지 않는다.
